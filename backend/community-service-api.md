# Community Service API Contract — Sprint 2

**Called through:** the API Gateway, `http://localhost:8080` (the service itself listens on `8081`, an internal detail)  
**API prefix:** `/api/v1`  
**Authentication:** JWT checked by the Gateway, which passes the caller as `X-User-Id`, `X-User-Name`, `X-User-Roles` (see `backend/identity-service/AUTH_CONTRACT.md`). Reading is public; writing needs a login.  
**Database:** `tounsiguide_community` (MySQL), owned by Community Service only.

## Design rules

- Angular calls the Gateway, never a service port or MySQL.
- The API exposes DTOs, not JPA entities.
- Posts own post content; comments belong to one post.
- **Places belong to the Location & Matching Service** (`docs/api/location-service-api.md`). A post only stores an optional `locationId`; the Community Service checks it exists by calling `GET /api/v1/locations/{id}` on the Location Service. It never copies the place name or coordinates.
- Only the author may edit a post or comment; the author or an administrator may delete it (`403` otherwise).
- Deleting a post also deletes its comments.
- `createdAt` and `updatedAt` are generated by the backend. Clients do not provide `id`, author identity, or timestamps.

## Posts

| Method | Path | Auth | Success | Purpose |
|---|---|---|---:|---|
| GET | `/api/v1/posts` | public | 200 | List posts. |
| GET | `/api/v1/posts/{postId}` | public | 200 | Read one post. |
| POST | `/api/v1/posts` | member | 201 | Create a post (author = caller). |
| PUT | `/api/v1/posts/{postId}` | author | 200 | Replace content and Location. |
| DELETE | `/api/v1/posts/{postId}` | author or admin | 204 | Delete post and its comments. |

### Create/update request

```json
{
  "content": "A useful local recommendation",
  "locationId": 12
}
```

`locationId` may be `null` (no place). On update, `null` removes the place.

| Field | Rule | Error when broken |
|---|---|---|
| `content` | Required, not blank, at most **2,000** characters | `400 VALIDATION_ERROR`, `details.content` |
| `locationId` | Optional; positive; must exist in the Location Service | `400 VALIDATION_ERROR`, `details.locationId` = `Location not found: {id}` |
| — | Location Service unreachable while checking `locationId` | `503 LOCATION_SERVICE_UNAVAILABLE` |

The frontend gets a `locationId` from the place picker: a directory result already has one, and a place picked on the map gets one from `POST /api/v1/locations/resolve`.

### Post response

```json
{
  "id": 1,
  "content": "A useful local recommendation",
  "authorId": "3f1c…",
  "authorName": "Sarra",
  "locationId": 12,
  "createdAt": "2026-11-08T12:00:00Z",
  "updatedAt": "2026-11-08T12:00:00Z"
}
```

To show the place, the frontend loads the Locations of all visible posts in one call: `GET /api/v1/locations?ids=12,4,7`.

## Comments

| Method | Path | Auth | Success | Purpose |
|---|---|---|---:|---|
| GET | `/api/v1/posts/{postId}/comments` | public | 200 | List comments for a post. |
| GET | `/api/v1/posts/{postId}/comments/{commentId}` | public | 200 | Read one comment. |
| POST | `/api/v1/posts/{postId}/comments` | member | 201 | Create a comment. |
| PUT | `/api/v1/posts/{postId}/comments/{commentId}` | author | 200 | Update a comment. |
| DELETE | `/api/v1/posts/{postId}/comments/{commentId}` | author or admin | 204 | Delete a comment. |

### Create/update request

```json
{
  "content": "This recommendation is useful."
}
```

| Field | Rule | Error when broken |
|---|---|---|
| `content` | Required, not blank, at most **1,000** characters | `400 VALIDATION_ERROR`, `details.content` |

A comment requested under a post it does not belong to returns `404 RESOURCE_NOT_FOUND` (`Comment not found: {id}`).

### Comment response

```json
{
  "id": 10,
  "postId": 1,
  "content": "This recommendation is useful.",
  "authorId": "3f1c…",
  "authorName": "Sarra",
  "createdAt": "2026-11-08T12:05:00Z",
  "updatedAt": "2026-11-08T12:05:00Z"
}
```

## Error response

### Resource not found — 404

```json
{
  "timestamp": "2026-11-08T12:00:00Z",
  "status": 404,
  "code": "RESOURCE_NOT_FOUND",
  "message": "Post not found: 999",
  "path": "/api/v1/posts/999",
  "details": {}
}
```

### Validation error — 400

```json
{
  "timestamp": "2026-11-08T12:00:00Z",
  "status": 400,
  "code": "VALIDATION_ERROR",
  "message": "Request validation failed",
  "path": "/api/v1/posts",
  "details": {
    "content": "Content must not be blank"
  }
}
```

Other codes in the same format: `401 UNAUTHORIZED`, `403 FORBIDDEN`, `503 LOCATION_SERVICE_UNAVAILABLE`.

### Not covered by the common format yet

Malformed JSON, a non-numeric path id and unexpected server errors are not handled by `GlobalExceptionHandler`. They currently return Spring's default error body, not the format above.

> **Updated 2026-11-08 (Sprint 2 alignment):** the Sprint 1 dummy-location catalog (`/api/v1/dummy-locations`) and the place fields stored on posts (`place.name`, `place.latitude`…) were removed. Places now live in the Location & Matching Service (8082); posts keep only `locationId`. The three dummy locations were migrated to the Location directory with the same ids (1, 2, 3).

## Request path

```text
Angular (4200)
  → API Gateway (8080): checks the JWT, adds X-User-* headers
  → Community Service (8081)
      → Post/Comment service layer ── GET /api/v1/locations/{id} ──→ Location Service (8082)
  → Repository
  → MySQL (tounsiguide_community)
```
